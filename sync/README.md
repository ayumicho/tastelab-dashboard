# TasteLab Dashboard Sync Module

## Overview

The `sync/` module orchestrates the ETL (Extract, Transform, Load) pipeline that synchronizes multimodal analysis data from MinIO object storage into the TasteLab dashboard database. It processes both NLP (Natural Language Processing) and Computer Vision analyses generated by the pipeline, maintaining data integrity and preventing duplicate imports.

## Architecture

### Data Flow

```
MinIO Storage
    ├── NLP Analysis (sentiment, insights, summaries)
    ├── CV Analysis (detections, tracking)
    └── Metadata & Transcripts
          ↓
    MinIOService (list & read)
          ↓
    minio_sync (orchestration)
          ↓
    data_import (parse & validate)
          ↓
    Database (PostgreSQL via SQLAlchemy)
```

## Module Reference

### 1. `minio_service.py`

**Purpose:** Provides a service layer for all MinIO object storage operations.

#### Key Methods

- **`_init_client()`**
  - Initializes the MinIO client using Flask app configuration
  - Loads credentials and connection settings from `config.py`
  - Called automatically on instantiation

- **`list_analysis_files(prefix="")`**
  - Scans the bucket for completed analysis files
  - Returns deduplicated list of videos with analysis results
  - Filters for `.chart_data.json` (NLP) and `.detections.json` (CV) files
  - **Returns:** List of dicts with keys: `path`, `date_folder`, `session_folder`, `video_name`, `last_modified`

- **`read_json_file(object_name)`**
  - Retrieves and parses a single JSON file from MinIO
  - Handles resource cleanup (closes response)
  - **Returns:** Parsed JSON dict or None on error

- **`load_video_analysis_data(date_folder, session_folder, video_name)`**
  - Aggregates all analysis artifacts for a specific video
  - Fetches from multiple paths:
    - NLP: `analysis/`, `insights/`, `sentiment_analysis/`, `summaries/`
    - CV: `cv_analysis/`
    - Transcripts: root session folder
    - Metadata: `tastelab-videos-sorted` bucket
  - **Returns:** Dict with keys: `chart_data`, `insights`, `sentiment`, `detections`, `metadata`, `transcript_base`


### 2. `data_import.py`

**Purpose:** Parses JSON analysis data and inserts records into the database with comprehensive validation.

#### Key Functions

- **`find_or_create_experiment(video_name, date_folder, session_folder)`**
  - Attempts to find existing experiment by partial name match, then exact match
  - Creates new experiment record if not found
  - Cleans folder names: `"muffin_taste_test_1200"` → `"Muffin Taste Test"`
  - **Returns:** Experiment object (created or existing)

- **`insert_analysis_data(session_data, date_folder, session_folder, video_name)`**
  - Main import function handling five data categories
  - Performs bulk operations for performance on large datasets
  - Prevents duplicate NLP analysis imports
  - Updates experiment metadata from analysis results

  **Processed Data Categories:**

  1. **Metadata:** Duration (seconds & minutes), participant count
  2. **Computer Vision:** Tracking analysis, detection data
  3. **NLP Analysis:** Sentiment summary, emotion percentages
  4. **Timeline Segments:** Per-segment emotion, sentiment, confidence scores
  5. **Supplementary Data:**
     - Chart Bins: Visualization timeline data
     - Keywords: TF-IDF and relevance scoring
     - Topic Sentiments: Discussion topics with emotion tracking
     - Detected Questions & Actions: Extracted from dialogue
     - Transcripts: Summary and preview
  6. **Text Insights:** Bigrams, trigrams, important sentences, action items, multi-emotion segments

  **Returns:** Experiment ID on success, None on failure

#### Data Model Coverage

The module populates the following SQLAlchemy models:

- `Experiment` - Session-level metadata
- `NlpAnalysis` - Analysis metadata & statistics
- `TrackingAnalysis` - Computer vision detections
- `EmotionData` - Emotion distribution across session
- `TimelineSegment` - Per-segment analysis (emotion, sentiment, text)
- `ChartBin` - Aggregated data for visualization
- `TranscriptSummary` - Text summaries and previews
- `Keyword` - Ranked keywords with scores
- `TopicSentiment` - Topic-level emotion tracking
- `DetectedQuestion` - Questions extracted from dialogue
- `DetectedAction` - Action items identified
- `TextInsight` - Complex text features and summaries

#### Error Handling

- Validates JSON structure with fallback defaults
- Safely parses timestamps and numerical values
- Normalizes emotion vectors and sentiment scores
- Rolls back transaction on failure
- Logs errors with full traceback


### 3. `minio_sync.py`

**Purpose:** Orchestrates the synchronization process with duplicate prevention and batch processing.

#### Key Functions

- **`sync_new_analyses(max_imports=None)`**
  - Main entry point for ETL pipeline
  - Scans MinIO for new analysis files
  - Checks database to prevent duplicate processing
  - Validates data presence before import
  - Supports batch processing to prevent timeouts
  - Logs progress and timing metrics

  **Deduplication Logic:**
  - Skips import if both NLP and CV analysis already exist locally
  - Continues if only one type is present
  - Validates data completeness before processing

  **Returns:** Dict with operation summary:
  ```python
  {
      'new_imports': 5,
      'skipped': 12,
      'errors': 0,
      'duration': 45.32  # seconds
  }
  ```

#### Performance Considerations

- Implements periodic logging every 10 files to track progress
- Records timing for list operations and individual file processing
- Batch limit (`max_imports`) prevents timeout on large sync runs
- Bulk insert operations for tables with many rows


## Configuration

The sync module requires MinIO credentials in `config.py`:

```python
MINIO_ENDPOINT = "minio-endpoint:9000"
MINIO_ACCESS_KEY = "access-key"
MINIO_SECRET_KEY = "secret-key"
MINIO_SECURE = True  # Use HTTPS
MINIO_BUCKET = "tastelab-processed"
```

The `tastelab-videos-sorted` bucket is used separately for metadata retrieval.

## Typical Workflow

1. **Trigger Sync:** Call `sync_new_analyses()` from a scheduled task or manual trigger
2. **List Files:** MinIOService scans buckets for new analysis files
3. **Check Duplicates:** Query database to see if video already imported
4. **Load Data:** Retrieve full analysis payload from MinIO
5. **Validate:** Check for required data (sentiment or detections)
6. **Parse:** Insert data with proper type conversion and normalization
7. **Commit:** Persist all changes to database
8. **Report:** Return summary of operation

## Error Handling & Logging

- **File Not Found:** Logged as info, continues to next file
- **Parse Errors:** Full traceback logged, import skipped, `errors` counter incremented
- **Duplicate Detection:** Silently skipped, `skipped` counter incremented
- **Database Errors:** Transaction rolled back, detailed error logged

All operations logged via Flask app logger.

## Performance Notes

- **Bulk Operations:** TimelineSegment, ChartBin, Keyword, TopicSentiment, DetectedQuestion, DetectedAction use bulk_insert_mappings for performance
- **Deduplication:** Prevents redundant NLP analysis parsing via query check
- **Batch Processing:** Use `max_imports` parameter to process files in chunks
- **Resource Management:** MinIO responses explicitly closed to prevent connection leaks

## Integration with Dashboard

The sync module integrates with the main dashboard via:

- **Models:** Uses SQLAlchemy models from `models.py`
- **Database Session:** Uses `db` session from Flask app
- **Configuration:** Loads from Flask app config
- **Logging:** Uses Flask app logger

Call `sync_new_analyses()` from a background task, scheduled job, or webhook handler to keep dashboard data synchronized with pipeline outputs.
